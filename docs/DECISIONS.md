## A. 架构与各部分怎么做的

### How it is put together

```

  protocol.ts    event names + payload types shared with internal/sshx
  events.ts      one subscription per topic, for the life of the app
  backend.ts     the only file that calls Go
  fsaccess.ts    native file pickers for trzsz (see "File transfer" below)
  highlight.ts   keyword colouring for output, with one vocabulary per line
  msyn.ts        MobaXterm .msyn import: colours, branch-by-branch compile
  terminal.ts    xterm + addons + TrzszFilter + highlighter, one instance per tab
  zmodem.ts      lrzsz (`rz`/`sz`) for hosts without trzsz: ZMODEM client, pickers, streaming
  store.ts       tabs, hosts, notices, settings, and the connect-time prompts (xterm stays out of the reactive graph)
  clipboard.ts   Wails clipboard first, navigator.clipboard as fallback

frontend/src/components/
  PassphraseDialog.vue  asks for an encrypted key's passphrase, at connect time
  PromptDialog.vue      one-field asks: a one-time code, an export passphrase
  SettingsDialog.vue    font (monospace only), word separator, highlight sets
  ConnectDialog.vue     the host form: jump host, two-factor, and the rest

frontend/bindings/      TypeScript proxies generated by wails3 — see "Wails v3"

app.go           the App service: bound methods + ServiceStartup/ServiceShutdown
files.go         native pickers + scoped, chunked file IO for trzsz
selftest.go      in-app self-test: drives the real SSH stack against a local server
main.go          application.Options: services, embedded assets, window, single instance
Taskfile.yml     wails3 build/dev/run targets (generated scaffold, trimmed)

                   jump-host tunnelling (direct-tcpip), keepalives
internal/fonts/    which installed font families are fixed-pitch (GDI)

internal/testutil  test-only temp dirs whose cleanup forgives Windows
internal/appdir    where state lives (override with GOTERM_DIR)

```

### Wails v3

The app runs on `wailsapp/wails/v3 v3.0.0` (the stable release; it was beta.34 while
the project was being built). The v2 → v3 jump is not a
version bump — the whole host/frontend seam moved:

- **`main.go` is an application, not a window call.** `application.New(Options{...})`
  takes `Services`, an `Assets.Handler`, `SingleInstance`, and per-OS blocks; the
  window comes from `app.Window.NewWithOptions` in the App service's startup.
- **Bound types are services.** `NewService(&App{})` / `NewService(&FileBridge{})`
  replace `Bind:`. v3 calls `ServiceStartup(ctx, ServiceOptions)` if a service
  implements it, which is where `App` and `FileBridge` wire themselves to the
  application (and where `App` keeps its `startup`/`shutdown` pair that the Go
  tests still drive directly).
- **TypeScript calls generated proxies.** `wails3 generate bindings -ts` writes
  `frontend/bindings/goterm/{app,filebridge}.ts`; `lib/backend.ts` imports those
  instead of the old hand-written `frontend/wailsjs` shims, and they resolve to
  `undefined` rather than throwing when no backend is reachable — which is what
  lets `npm run dev` run UI-only.
- **Events and clipboard come from `@wailsio/runtime`.** `Events.On(name, e => …)`
  hands you an envelope (`e.data`); `Clipboard.Text()` / `SetText()` replaced the
  v2 `window.runtime` globals, so the bridge is a normal package import.
- **Nothing mounts until the bridge answers.** On Wails the app waits for
  `common:WindowRuntimeReady` (or 4 s), then retries `App.Ping` before it reads
  state, because the webview can load before the Go services are reachable —
  otherwise the first launch reads an empty host list and shows the welcome
  screen over a working backend. `bridgeReady` therefore means "`Ping`
  answered", and it also gates whether trzsz gets the Go-backed file pickers.
- **Tests mock the runtime.** `frontend/src/test-setup.ts` stubs
  `@wailsio/runtime`, because importing the real one starts a heartbeat against
  a desktop that is not there; vitest also skips the `wails()` Vite plugin via
  `VITEST`.
- **Go 1.26 is not optional.** Wails requires 1.26, so the toolchain is Go 1.26
  (v3.0.0, now the stable release, still declares `go 1.26.0`).

### File transfer

`tsz`/`trz` are intercepted by trzsz, but trzsz was written for browsers: a
download means `window.showDirectoryPicker()`, which needs a secure context
*and* transient user activation — neither of which it reliably gets in a
webview, and the transfer banner arrives long after the keystroke that caused
it.

So `lib/fsaccess.ts` replaces those two browser functions with implementations
that call Go (`files.go`): you get a real Explorer dialog, and the bytes move
through chunked `ReadRange`/`WriteChunk` calls. Downloads are buffered to ~1 MiB
per bridge call instead of one per 32 KiB chunk. A transfer's file names are
sanitised, and the Go side refuses any path outside a folder you actually
picked in this session — a hostile server cannot turn `tsz` into arbitrary file
writes. The status bar shows which picker is live (`native picker`).

Three things had to line up before that worked, and each of them failed
silently in its own way:

- **The banner has to reach trzsz.** Server output used to go straight to
  xterm, so `::TRZSZ:TRANSFER:R:1.2.0:` was printed as text and the filter never
  saw it. Everything now goes through `ServerOutputStream` →
  `TrzszFilter.processServerOutput`.
- **The banner has to arrive whole.** The pump batches by time and size, so the
  banner can be split across two events, and trzsz only looks for it inside one
  chunk (and only in at least 26 bytes — the banner plus its newline). A
  trailing fragment that could still grow into a banner is held back for one
  chunk, with a 120 ms timer so a shell prompt ending in `:` is never lost.
- **trzsz-js 1.1.6 crashes on a banner with no unique id.** It reads the id and
  calls `id.length` on `undefined` inside a detached promise: no error, no
  dialog, just the banner on screen forever. trzsz 1.2.0 on the remote sends
  exactly that shape. The smallest id that satisfies the check is inserted on
  the way in and removed again on the way to the screen, so the terminal still
  shows exactly what the server sent.

**The context menu's “Upload files…” sends `trz`; it does not fake a drop.**
The first version opened a hidden `<input type=file>` and rebuilt a
`DataTransferItemList` out of the chosen files, because that is the type
`trzsz.uploadFiles()` takes. Script-made items have no filesystem entry —
`webkitGetAsEntry()`, which is exactly what trzsz calls, returns null for them —
so the user picked real files and was told “No files to upload”. Now the menu
sends `trz` through the same path a keystroke uses, and trzsz's own banner
handler opens the native picker and streams the files: the one path that already
worked when you typed `trz` by hand.

- **The banner has to reach trzsz.** Server output used to go straight to
  xterm, so `::TRZSZ:TRANSFER:R:1.2.0:` was printed as text and the filter never
  saw it. Everything now goes through `ServerOutputStream` →
  `TrzszFilter.processServerOutput`.
- **The banner has to arrive whole.** The pump batches by time and size, so the
  banner can be split across two events, and trzsz only looks for it inside one
  chunk (and only in at least 26 bytes — the banner plus its newline). A
  trailing fragment that could still grow into a banner is held back for one
  chunk, with a 120 ms timer so a shell prompt ending in `:` is never lost.
- **trzsz-js 1.1.6 crashes on a banner with no unique id.** It reads the id and
  calls `id.length` on `undefined` inside a detached promise: no error, no
  dialog, just the banner on screen forever. trzsz 1.2.0 on the remote sends
  exactly that shape. The smallest id that satisfies the check is inserted on
  the way in and removed again on the way to the screen, so the terminal still
  shows exactly what the server sent.

If a transfer fails anyway, the `#FAIL:` frame trzsz sends back is decoded
(zlib + base64) and shown as a toast instead of disappearing.

**Cancelling is not failing, and must not look like a crash.** Two things used
to go wrong when you stopped a `trz`/`tsz` in flight:

- trzsz-js writes its closing words through Node's `process.stdout`, which a
  webview does not have — so the exit handler threw *“process is not defined”*
  from inside the library, after the cancel itself had already worked. The app
  now gives it a stdout (`bindTrzszStdout`) that writes into the terminal, and
  filters what comes out: the escape sequences that tidy the progress bar always
  arrive, while the narration of a stop (`Stopped and deleted`, `transfer
  canceled`, `^C`, `received interrupt signal`), a Go panic from the remote
  binary, and the library's own `decode [...] error:` are dropped.
- The same text reached the user as a red toast. It no longer does: the
  `#FAIL:` handler, the upload rejection and the stdout sink all ask
  `isTransferCancel()` first. A real failure — disk full, permission denied, a
  checksum mismatch — is still said out loud, because that is the one the user
  has to act on.

**lrzsz (`rz` / `sz`) for servers without trzsz.** trzsz has to be installed on the far side; plenty of hosts only ship lrzsz, and there `rz` printed `**\x18B00…` on the screen and waited for a ZMODEM client that never came. `lib/zmodem.ts` is that client: every server byte passes through it before the terminal, and once a session is confirmed the protocol owns the stream — nothing else sees those bytes, and keystrokes are held back because typing into a packet would corrupt the file. An offered file asks for a folder through the *same* native dialog as `tsz` and streams into it; `rz` opens the picker and streams out.

**`rz` uploads died while the file picker was open; that is fixed.** The direction decides who waits: with `rz` on the server *we* are the sender, and a human has to pick a file before anything can go out. zmodem.js spends that wait on a five-second “keepalive” that sends a ZSINIT and then accepts nothing but its ZACK, while lrzsz's `rz`, waiting for ZFILE, polls back with **ZRPOS** at the offset it wants. The library met that poll with `Unhandled header: ZRPOS`, thrown out of `Sentry.consume()`; the pipe caught it, switched the scanner off, said so — and left the session object in place, so keystrokes stayed swallowed and `rz` waited forever. That is what made the tab look hung. Two things changed. While a file dialog is open the pipe answers the “still here” headers (`ZACK`, `ZRINIT`, `ZRQINIT`, `ZRPOS`, `ZSINIT`) with a no-op — whatever the library armed itself still wins, and anything that carries meaning (`ZFILE`, `ZDATA`, `ZEOF`, `ZSKIP`, `ZABORT`) still throws, because swallowing those turns a failure into a hang. And a session that throws is now **ended**: the far side gets an abort, the keyboard comes back, and the notice says the transfer stopped and `rz` can be run again. Pinned by `a receiver that polls while the picker is open` in `zmodem.test.ts` — time is advanced past the keepalive, the peer pokes with the library's own `_send_header('ZRPOS', 0)`, and the upload still completes; a second test asserts a session that throws is no longer `active()`.

**A progress line for `rz` / `sz`, drawn by trzsz's own renderer.** Both lrzsz programs paint their progress on the *server's* tty, which this window never shows, so a large transfer used to be silent from start to finish. The pipe counts the bytes it moves — for a download, the packets arriving against the size the ZFILE announced; for an upload, the local file's size against the offset already sent — and hands them to the very class `trz`/`tsz` use, `TextProgressBar`, driven in the order trzsz's transfer code drives it (`onNum`, then per file `onName` / `onSize` / `onStep` / `onDone`). So both kinds of transfer print the *same line*, because it is the same code: `(1/2) backup.tar [████░░░░] 45% | 5.6 MB | 1.2 MB/s | 00:12 ETA` — in the terminal, where trzsz draws it, so the app needs no per-tab transfer state, no markup and no styling for it. **Why it is vendored rather than imported:** the package exports only `TrzszAddon` and `TrzszFilter`, so `TextProgressBar` sits inside the bundle and is unreachable. `frontend/src/vendor/trzsz/progress.ts` is that file **verbatim** (MIT, © Lonny Wong, taken from the published `lib/trzsz.mjs.map`, version 1.1.6), with a few-line `comm.ts` beside it declaring the one type the file imports, so upstream needs no edits at all; the only line added is `// @ts-nocheck`, because this tsconfig is stricter than theirs. Identical output is the payoff, and copying an upstream change by hand is the cost (the file has not moved since 1.1.6). Three pieces of glue live in `zmodem.ts`: `onStep(0)` puts the bar up at once (trzsz paints only on the first packet, and a large file spends seconds in the handshake); completion is decided by the **byte count** rather than by the session ending, because ZFIN can arrive while the last bytes are still being written to disk; and a newline is written before `showCursor()`, since trzsz's bar repaints in place and leaves the line to whatever prints next — here, the shell prompt.

**The one ZMODEM case still unsupported: a sender that leads with a bare ZFILE.** lrzsz's `sz` announces itself with **ZRQINIT**, and that is what wakes the session — which is why a download works on a host that has nothing but lrzsz. A sender that skips that line and starts at **ZFILE** is not picked up at all: the scanner wakes on ZRINIT/ZRQINIT only, so the header scrolls past as text. Answering a bare ZFILE with a hand-built session was implemented and measured, and it is worse — the session aborts with “CRC check failed!” on the header it was handed, trading silence for a false error — so it was reverted. `frontend/src/lib/zmodem.test.ts` pins that gap with a test named for it, so it fails the day it is fixed rather than being quietly believed fixed.

The direction is never guessed — the first header decides: **ZRQINIT** means the far side wants to send (so we receive), **ZRINIT** means it wants to receive (`rz`), so we send. A sender that leads with a bare ZFILE is the gap described above. Cancelling either dialog is answered properly rather than left hanging (`ZSKIP` / `ZFIN`), a failed write aborts the session instead of reporting a file that never landed, and a name like `../../etc/passwd` in the header is reduced to a bare file name inside the folder that was just chosen.

Ordinary output does not pay for the scanner: a chunk with no `*` in it goes straight to the screen. The subtlety is what happens at a chunk boundary, and it took a review to catch the first attempt at it. A ZMODEM header is 21 bytes — `**`, ZDLE, then hex — so the chunk that *finishes* a header contains no asterisk at all, and the Go pump splits output by time and size without asking the protocol's permission. Two things follow:

- The **tail** of a chunk that could still grow into a header is held back (at most 20 bytes, released by the next chunk or by a 120 ms timer) and offered again with it. It cannot be left to the scanner: zmodem.js keeps the *first* 21 bytes of its detection cache (`cache.splice(MAX_ZM_HEX_START_LENGTH)` truncates to the head), so a `**` at the end of a 64 KiB chunk is gone before the rest of the header arrives — which is exactly how a real `sz`/`rz` session started and never finished.
- The hold is **precise**: only a tail that still matches the start of a header (`*`, `**`, `**`+ZDLE, then hex) waits, and only while it is shorter than a header. `echo *.txt` is not a header and must not be held, and a complete header already in hand must be judged now rather than waited for. A flag that simply switched the fast path off "until things settle" is worse than the bug: one asterisk anywhere in the output — `ls *`, `**kwargs`, a C comment's `*/` — would have copied every later 64 KiB chunk into the scanner for the life of the tab.

And the scanner is not trusted with the user's bytes: it runs inside a `try`, because zmodem.js spreads its input through `Function.prototype.apply` and gives up past roughly 131 072 bytes (Go's cap is 64 KiB, so this is a net and not a hot path). If it ever throws, the bytes go to the screen, one notice says the scan is off for this session, and the pipe stays out of the way afterwards.

A session owns the stream, which means typing is set aside while it runs — that is invisible the first time, so it is said once. And it cannot be forever: a far side that dies mid-handshake would otherwise leave a tab that swallows every keystroke, with no way out except closing it. So the pipe watches the traffic, and **45 seconds of silence from the server ends the session** and says so. Traffic in either direction resets that clock, including a sender retransmitting its header while the folder dialog is open, so a working transfer is never cut off.

The protocol itself is [zmodem.js](https://github.com/FGasper/zmodemjs) (Apache-2.0), whose own suite runs against real lrzsz binaries — the part written here is the routing, the pickers, the file IO and the lifecycle. Its `Session` API is also what the tests use for the far side, so nothing is asserted against a hand-written frame: `sz` and `rz` are driven as real sessions over a two-way wire, and that is how the `files_remaining` off-by-one (ZMODEM counts the current file, and rejects `0`) was caught.

### Keys, passphrases, and where secrets live

An encrypted private key is not a form field. The host form used to have one box
labelled "Key passphrase" whose value went into the *password* field, so the
passphrase never reached Go and every key connection failed with "private key is
encrypted". There is no such field any more:

1. Go tries to sign with the key. If it is encrypted (or the stored passphrase
   is wrong), the error is wrapped in `sshx.ErrPassphraseRequired`.
2. The frontend matches that wording (`needsPassphrase`) and opens
   `PassphraseDialog` — the ask happens at the moment it is needed, with the
   failing message shown if the first answer was wrong. Which of the two keys is
   being asked about comes from Go's marker, `passphrase required (proxy): …`,
   and never from the message text: the target's own key may well be named
   `proxy.pem`, and that used to send its passphrase to the jump host's field —
   a prompt that appeared to do nothing.
3. The answer is retried immediately. It is used for that attempt only and
   reaches the OS key ring **only** if the user ticks "remember", and it then
   lands as the host's own secret (a jump host's passphrase is stored as the jump
   host's secret — different machine, different item).

**A password that was never stored is the same kind of question.** Save a host
with the password box empty and the old code answered a double-click with
"has no saved password: edit the host and enter it again" — an error with no way
forward, while an encrypted key in exactly that situation opened a prompt. Now Go
refuses with a marker (`hoststore.ErrPasswordRequired`: `password required:`, and
for the jump host `password required (proxy):`) and the frontend asks:

- It asks **before dialing**, because it can already see there is nothing to send
  (`hasSecret` is on the host row the sidebar renders). An empty password sent to
  the server is a failed login charged to that account — possibly to a lockout —
  for a mistake GoTerm can see on its own side.
- The marker is the backstop for when the key-ring entry has gone or the list is
  stale, working exactly like the passphrase marker.
- Answers travel to Go as `ConnectAnswers` — a struct, not five positional
  strings, because three of them are per-machine secrets and the project has
  already shipped a bug where one answer landed in another machine's field. A
  typed password is used for that attempt and forgotten unless "remember" was
  ticked; a two-factor code is still appended to whichever password is in use.

`hosts.json` still holds no secrets, and a passphrase typed at the prompt is
never written to disk unless "remember" was ticked.

### Jump hosts (SSH proxy)

A host can be reached through a bastion: GoTerm dials the jump host first, opens
a `direct-tcpip` channel to the target, and runs the target's own SSH handshake
**end to end over that tunnel**.

- The jump host needs nothing but a normal sshd with `AllowTcpForwarding yes`
  (the default). No shell access, no tooling, no agent forwarding.
- It never sees the session: it carries opaque bytes it cannot read.
- Its host key is pinned **separately** in `known_hosts.json`. Trusting the
  bastion proves nothing about the target, and a `strict` policy applies to
  whichever endpoint you set it on.
- Its credential is a second secret item (`host/<id>/proxy-secret`), so the
  bastion's password is not the target's password by construction.
- Errors say which machine refused: `jump host 203.0.113.7: authentication
  failed …`, `jump host … refused to forward the connection — its sshd has
  AllowTcpForwarding off`.
- An **encrypted jump-host key** asks for its passphrase at connect time, the same
  way the target's does, and the prompt is titled "Jump-host key passphrase" so
  it is never mistaken for the target's key.
- A **PuTTY `.ppk` is refused with instructions**, not as a mystery: `x/crypto`
  cannot read that format, so no passphrase could ever unlock it and the login
  would just fail. GoTerm says to export it from PuTTYgen as an OpenSSH key.
- The status bar shows `via user@bastion:port` so a tunnelled session is never
  mistaken for a direct one.
- **Every step of a connect is timed.** The socket, the SSH handshake on it, and
  the jump host's channel open all fall under the 20 s dial timeout. That is not
  decorative: `x/crypto/ssh` never sets a deadline (its only `SetDeadline` is a
  stub that answers "deadline not supported"), so `ClientConfig.Timeout` bounds
  the TCP connect and nothing else. A peer that accepted the connection and then
  went quiet — a dead port-forward, a bastion aimed at nothing — used to leave
  the window on “connecting…” until the app was killed. `internal/sshx/stall_test.go`
  keeps a silent listener open and asserts that the connect returns
  `no answer from … within …` instead.

### Two-factor logins (JumpServer and friends)

Tick **Two-factor authentication** on a password host and every connect starts
with a prompt for the one-time code. That is the whole configuration; nothing
about the code is stored.

- Go appends the code to the saved password (`password` + `123456`) and sends
the result — the form of 2FA that these bastions actually accept. The password
never reaches the webview, so the prompt asks for the code only.
- The code is asked for **before** the first attempt. Waiting for a refusal to
find out a code is needed burns a 30-second window and tells you nothing.
- If the server refuses anyway (an expired code), the prompt comes back with
the refusal quoted and a fresh attempt behind it. Cancel means cancel — no
silent password-only retry.
- The checkbox is only offered for password auth, and saving it with key or
agent auth is refused: with no password there is nothing to append a code to,
and a box that does nothing is worse than no box.

The local demo server can demand a code too: `sshtest -2fa` accepts
`goterm-dev123456` but refuses `goterm-dev`.

### Tabs: reorder, reconnect, duplicate

**A tab whose session has ended goes quiet.** A closed tab stays mounted — it has
to show the "connection closed" strip — so it still receives everything a live
one does: the focus-in sequence xterm emits when you switch back to it, mouse
reports when the program had asked for the mouse, and the anti-idle's nudge.
Those used to be sent, refused ("session is closed") and turned into a toast each
— so returning to a dead tab filled the corner with copies of one sentence. Now
input for a tab that is not `open` is dropped where it arrives, a refusal from Go
marks the tab once and writes the reason into the pane instead of the corner, and
the anti-idle timer for a closed session is stopped. Identical notices are also
collapsed within four seconds: the same sentence twice is an echo.

**Drag a tab along the strip to reorder it.** The move is live — hovering another
tab while dragging drops the dragged one into that slot, so the strip is always
showing the outcome instead of a preview — and the dragged tab is faded while it
travels. Nothing behind the tabs notices: a terminal is held by tab id and the
keyed DOM nodes are moved rather than recreated, so xterm, the SSH session, its
keepalive and any transfer in flight stay exactly as they were. Order is a paint
order, not state; it is not persisted, because nothing about tabs is.

Right-click a tab for two things a terminal user asks for constantly. The menu
lists **Duplicate** first and **Reconnect** second: duplicating costs nothing and
is what an open tab is asked for most, while reconnecting is what a dead one
needs.

**Reconnect** closes the tab and dials that saved host again — including the
passphrase / two-factor prompts, exactly as the first connection did. Ad-hoc
(`Ctrl+T`) sessions have nothing stored to dial, so the entry is disabled with
that reason in its tooltip rather than sitting there dead.

**Duplicate** (the menu entry reads just that) opens a second terminal on the connection that is already
up: `Manager.Duplicate` calls `NewSession()` on the existing `*ssh.Client`, so
there is no second handshake, no password, no key passphrase and **no second
one-time code**. `TestDuplicateOpensASecondTerminalWithoutAnotherLogin` pins that
against the real server by counting authentications: one before, one after.

What sharing means in practice:

- Two real shells. Each tab types into its own channel and sees none of the
  other's output.
- Closing either one leaves the other working — the client is refcounted
  (`internal/sshx/link.go`), so it is torn down only when the last session using
  it is gone, along with the ssh-agent handle and any jump-host tunnel riding on
  it.
- One keepalive loop per **connection**, not per tab: five duplicates still mean
  one probe every 45 s. If those probes stop being answered, *every* session on
  that connection reports `connection lost` — not only the one whose probe
  failed.
- Duplicating a session whose connection is already gone is refused; opening a
  tab that looks alive but cannot type would be worse than saying no.

**Pane size.** The PTY is told the size of the pane looking at it — always, on every path that hands a session to a tab. That sounds like a detail until it is not: a tab is created and its dial starts in the same tick, but the pane is only measured a frame later, so the fit happens while there is no session to tell and the PTY is left at the size it was dialled with (`100x30` on the first tab, the last pane's geometry after that). Adoption used to send a resize only when that fit *changed* something — which by then it never had — so a session stayed `100x30` inside a `170x45` window and `htop`, `less` and `systemctl status` painted a small screen in the corner until a window resize forced a difference. `frontend/src/lib/pane-size.test.ts` reproduces exactly that: bridge fitted while the dial is in flight, then prove the resize is sent anyway.

### Keepalives: staying connected while you think

Every session sends an SSH keepalive every **45 s**: a global
`keepalive@openssh.com` request with want-reply, the same mechanism OpenSSH's
`ServerAliveInterval` uses.

**A keepalive is not a way to keep a login open for ever.** The SSH keepalive is
there so a session does not die of someone else's idle timer; the anti-idle is
there because `TMOUT` counts input, not traffic. Neither is meant to outlast the
organisation that set those timers, so every connection also carries a hard stop:
**12 hours by default, 1–24 configurable** (Settings → Session lifetime). At the
deadline Go closes the connection and says why — `maximum session lifetime
reached (12 hours)`, with the usual Reconnect strip underneath.

Three properties make it a limit rather than a suggestion:

- The clock belongs to the **connection**, not to the tab: a duplicated session is
  another channel on the same login, so it shares the remaining time instead of
  buying a new window.
- Lowering the setting applies **immediately**, because the deadline is
  `connected at + cap`, never `now + cap`. Twelve hours in, set it to one and the
  session ends.
- Go clamps whatever it is told to 1–24 and reads 0 or nonsense as the 12-hour
  default, so neither a stale UI nor a hand-edited settings file can ask for an
  endless session.

Reconnecting is allowed and starts a new one: the property being kept is that
GoTerm never silently holds a session past the limit, not that the limit is
inescapable.

- **Nothing is written to the PTY.** A newline would be input, and a shell
holding a half-typed command would run it. This is the one thing a keepalive
must never do, and `TestKeepAliveNeverWritesToThePty` pins it: the repeater
shell echoes everything it reads, so an idle session that grows output would
fail the test.
- A tunnelled session pokes the bastion as well. The target can be perfectly
happy while the jump host's own idle timer (JumpServer: 30 minutes) closes the
socket underneath it.
- Three unanswered probes in a row mean the link is gone. That is how a dropped
network — which never reports anything by itself — turns into a visible
`connection lost` in the tab instead of a terminal that looks alive and eats
keystrokes. The wait for each reply is bounded, so a peer that vanished without
closing the socket cannot wedge the loop.
- `Config.KeepAliveSeconds` overrides the interval (`0` = default, negative =
off); the status of each session reports the resolved value.

**A keepalive is not enough, and saying otherwise would be a lie.** The request
above never touches the PTY — which is what makes it safe — and that is also why
it cannot satisfy a *shell* that has `TMOUT` set. Bash measures "waiting for a
complete line": after `TMOUT` seconds without one it prints
`timed out waiting for input: auto logout` and exits, with the transport in
perfect health. That is the message a user reads as "the keepalive is broken".

So there are two layers, and the settings screen names them separately:

| Layer | What it resets | Cost |
| --- | --- | --- |
| SSH keepalive (`keepalive@openssh.com`, 45 s) | load balancer / NAT / sshd idle timers, `ClientAliveInterval` | nothing — no bytes reach the shell |
| Anti-idle (**off by default**, Settings → Idle sessions) | bash/zsh `TMOUT`, and a bastion's "user activity" timer | a space and a backspace (default), an empty line, or a bare space, after the idle window |

**The nudge is a space followed by a backspace.** Two keystrokes that cancel each
other out: the line comes back exactly as it was typed, nothing is submitted,
nothing can run — and it is still *input*, which is the only thing `TMOUT` and a
bastion's activity detector count. That last part is why it replaced the empty
line: a session parked at a `>` continuation prompt, with half a loop already on
the line, could never be nudged by an Enter without running the loop, so it was
nudged by nothing and got logged out on schedule.

A NUL was tried and does not work: against a direct SSH login and a JumpServer
session, both timed out on it where the same sessions survived on real input.
`\x1b[0n` is worse than useless on its own terms — the bytes this feature sends go
**into the PTY**, so readline reads `ESC [ 0 n` as a meta prefix followed by junk
landing on the command line. A device status report is something a terminal says
to the host; it is not something a user types.

**An empty line is still available** (Settings → Idle sessions) for a shell that
only resets its timer on a completed line. It costs a new prompt each time.

**And a bare space, no backspace** — for the case the other two cannot reach.
Inside a full-screen program (an `ssh` chat client, a TUI with an input box that
times you out) the timer stands down, because a space there is a keypress with a
meaning. This third mode is the deliberate exception: it is one real keystroke
that stays where it lands, which is exactly what an input box's own idle timer
counts. The cost is in the name of the setting — the space remains in whatever
has focus until something deletes it. So it is opt-in, the dialog says so when it
is picked, and it is the wrong choice for `less` (a space pages down), `fzf` (a
space selects the current item) or an editor (it inserts).

The one case where "cancels out" is not automatic: a program that reads raw bytes
*without* switching to the alternate screen would see both keystrokes instead of
netting them out. In canonical mode the line discipline erases the space before
any program reads it, and readline does the same blind (a `sudo` password prompt
is unaffected), so this is a corner, not a routine — and the empty-line mode is
the fallback if one is ever in play.

Either way the anti-idle spends its effort on keeping the nudge rare and
harmless:

- **An empty line is never sent while you have unsubmitted input.** That Enter
would run the half-typed command. `Ctrl-C` and `Ctrl-D` count as clearing the
line. (The space pair has no such rule — it is allowed exactly *because* it
cannot submit anything.)
- **Never in a full-screen program** — unless the configured nudge is the bare
space, whose whole purpose is to be typed into one. While the alternate screen is
active (vim, less, htop) the space-and-backspace and the empty line both stand
down, because a space there is a keypress with a meaning — including when keyword
colouring is switched off, which is why the highlighter tracks that state
unconditionally.
- **Not in the middle of an output burst.** Five seconds of quiet first, so a
keystroke never lands while a program is halfway through printing. It no longer
waits for the whole idle window to be silent: a session that prints now and then
is exactly the session that used to be spent quietly dying.
- **Never during a transfer.**
- **It gives up rather than make a mess.** After sending, it counts what comes
back: one line is a prompt and fine, five or more means the far side reprinted a
screenful — a bastion's "choose an asset" menu does exactly that — so it stops
nudging that session and says so once, instead of scrolling the screen every few
minutes.

When a shell does time itself out anyway, the session says so once — with the
reason — and the toast carries a **Turn on** button that enables anti-idle
(3 min, whichever nudge is configured — the space by default) right there,
instead of leaving the user to guess why a playback of "auto logout" ended the tab.

### Moving hosts between machines (export / import)

`Export` in the sidebar footer writes every saved host — **passwords and
jump-host passwords included** — into one file, and `Import` reads it back:

- The file is sealed with a passphrase you choose: scrypt (N=2^15) derives a
key, AES-256-GCM encrypts the whole bundle, and the result is one opaque JSON
file. Names, addresses and passwords are all inside the ciphertext, so the file
is safe to mail to yourself.
- Only GoTerm can read it, and only with that passphrase. There is no recovery
if it is lost — the file is the key ring's contents, not a pointer to them.
- Export happens *after* the passphrase is typed: the file is written already
sealed, so no plaintext copy ever sits on disk waiting to be encrypted.
- Import matches an entry by id, then by address + user + port. Importing the
same bundle twice updates hosts instead of duplicating them; a bundle from
another machine's ids lands with fresh local ids.
- A secret is only written when the bundle carries one, so importing a
secret-free file cannot wipe a password that is already stored here. Secrets the
exporting key ring would not hand over are counted (`missing`) and reported
instead of being quietly dropped.
- Key paths travel verbatim: a `C:\Users\me\.ssh\id_ed25519` on one machine is
not that path on the next, and pretending otherwise would produce a host that
fails at connect time for a confusing reason.

### Settings: font, word separator, keyword colouring

The gear at the right of the status bar (or `Ctrl+,`) opens a dialog whose
changes apply to every open tab immediately and are remembered. It is split into
tabs — **Appearance** (font, background, remote encoding), **Behaviour** (word separator,
selection and paste, idle sessions, session lifetime) and **Highlighting** (keyword
sets, custom rules, `.msyn` import) — so a setting is one click away instead of a scroll, and
the dialog reopens on the tab used last. Switching tabs only shows and hides
sections, so a half-typed custom rule survives a look at the font list.

**Font — monospace only.** The list is not a guess and not a free-text field:
Go asks GDI (`EnumFontFamiliesEx`) for every installed face and keeps the ones
whose `lfPitchAndFamily` says fixed-pitch. A proportional face cannot render a
terminal grid — `il1W` come out at different widths inside fixed cells — so
there is nothing to choose there. `Consolas`, `Courier New`, `Lucida Console`
and the fixed-pitch CJK faces show up; `Arial` does not, and the test asserts
exactly that. The preview under the selector renders the real thing at the real
size, and a family that gets uninstalled later keeps its slot in the list rather
than being silently rewritten.

**Block and box characters.** `dust` draws one row of block characters per
directory. xterm can paint the block range (U+2580–U+259F) and the box-drawing
range itself instead of asking the font — `customGlyphs`, on by default — and it
paints them across the *whole* cell, including the 15% line-height padding this
app uses. Two stacked rows then have nothing between them, and eight bars come
out as one solid staircase. That reproduced outside the app: the same eight rows
rendered through xterm 6 with the WebGL renderer came out as one fused shape with
the default, and as separate bars with the font's own glyphs. The font keeps the
padding, so that is now the default — and the same pair of renders shows the
price, which is not hidden: a `│` from the font does
not span the padding either, so a TUI's vertical frame lines pick up a hairline
gap. Because that is a taste call, **Appearance → Block and box characters**
switches it back, live (`term.options.customGlyphs` plus `term.refresh`; the
renderer rebuilds its glyph atlas on that option, so no tab has to be reopened).
One or the other: separated bar charts, or seamless TUI frames. (If the GPU
context is lost the app falls back to xterm's built-in renderer, which always
draws from the font — there the switch has nothing to say, and bars are separate
anyway.)

**Remote text encoding.** Bytes reach xterm untouched — that is the point of the
app — so when Chinese arrives as mojibake the bytes really are not UTF-8, and no
font, locale or renderer setting will fix it: an older host set to `zh_CN.GBK`
sends GBK, and xterm decodes UTF-8 only. That was checked before anything was
built (every file in `frontend/src` is valid UTF-8, `index.html` declares UTF-8,
the machine has 205 CJK-capable faces, and a headless render of Chinese and of a
tabular table through the same xterm build with this app's font stack came out
perfect). **Appearance → Remote text encoding** therefore puts a `TextDecoder` in
front of the screen: UTF-8 stays the identity path (the very same `Uint8Array`
comes back, so the byte-for-byte guarantees have nothing to drift to), while
GB18030/GBK/GB2312, Big5 and Shift_JIS decode in **streaming** mode — a two-byte
character split across two output chunks must not become two replacement
characters. A change applies to every open tab at once, and throws away the
half-character the previous decoder was holding.

What it does not do is translate what you *type*: the browser has no GBK encoder,
so input is always sent as UTF-8. A host that expects GBK on the way in wants
`export LANG=zh_CN.UTF-8` instead — which also makes the encoding switch
unnecessary.

**Word separator.** Same idea as xterm's own option, exposed: the characters
that end a word for double-click selection. `/var/log/access.log` selects the
whole path with the default separator; drop `/` and `.` and it selects what you
actually meant. The dialog shows what a double-click would pick, live. An empty
separator is refused — it would make every line one word.

**Idle sessions (anti-idle).** Off by default. Tick it and GoTerm nudges the
session after 1–120 minutes of silence (default 3, deliberately below the usual
5-minute `TMOUT`), with a choice of what it sends: **a space and a backspace**
(the default — invisible, cannot submit or run anything, and it works even at a
`>` prompt with half a command on the line), **an empty line**, for a shell that
only resets its timer on a completed line, or **a bare space with no backspace**,
for the full-screen program the other two deliberately stay out of — one real
keystroke, which is what an input box's own idle timer counts, and which stays in
that box until you delete it. A NUL byte is not offered because it
was tried against a direct login and a JumpServer session and both still timed
out. Picking the bare space shows what it costs right there in the dialog. A nudge
only fires when it is safe: never during a transfer, never before five seconds of
quiet output, never with an empty
line while text is unsubmitted, never in a full-screen program unless that is the
mode you chose, and it stops for the session if one nudge makes
the far side reprint a screenful — see *Keepalives* above for the reasons.

**Window frame.** The title bar and the hairline border are drawn by the OS, and Windows only consults *its own* light/dark setting for them — so a dark GoTerm on a light-mode Windows used to sit under a white caption with a white border around it, whatever the app's own theme said. Now every theme switch tells Go, and Go tells Windows: `internal/wintheme` sets `DWMWA_USE_IMMERSIVE_DARK_MODE` and, on Windows 11, the caption, caption-text and border colours taken from the app's own tokens (`--bg`, `--text`, `--border`), so the frame meets the tab strip without a seam. The window's Wails theme is pinned instead of following the system, because otherwise a Windows theme change would repaint the frame in the system's colours and quietly undo this.

What each Windows can do: **Windows 11** gets the exact colours; **Windows 10 / Server** understands only the dark flag, so its caption is the system's dark grey rather than `#0b0f14` — dark either way, which is the point. On macOS and Linux the frame is the platform's own and this is a no-op. `tools/frame-check.ps1` asks DWM what the frame actually is, which is the only honest check: `PrintWindow` (what `gui-check.ps1` captures) shows a stale legacy frame from a cold start, and a screenshot cannot be taken from a non-interactive session at all.

**Background.** A colour picker, six presets (black, Solarized dark/light, Nord, Gruvbox, sepia) and “use theme colour”. The pane may be any colour, so **the pane decides the ink**: `panePalette` compares the chosen colour against both palettes and paints with whichever foreground contrasts better with it — light text on a black pane, dark text on a white one, and a mid-grey lands on the side that actually reads. That is the difference between a rule and a warning: the old behaviour kept the theme's text colour and *mentioned* it in the dialog, which left a black pane under the light theme as black text on black. The window chrome (tabs, sidebar, status bar) still follows the theme, so the dialog says when the two disagree; “use theme colour” hands the pane back to the theme entirely. **That includes the active tab**: it used to be painted with the pane's colour so it would merge with the terminal — which meant a dark custom background left one dark tab sitting in a light window. A canvas colour belongs to the canvas; `frontend/src/components/chrome-theme.test.ts` scans every component and fails if a `--term-` token appears outside the two files that legitimately paint it (`TerminalPane.vue` for the canvas, `SettingsDialog.vue` for the terminal preview). The pane behind the canvas is painted through a CSS variable, and that variable carries the same ink decision (`--term-fg`), so the settings preview cannot disagree with the terminal next to it.

**Keyword colouring (the MobaXterm-style filters).** Five built-in sets:
shell commands, bash scripts, nginx logs, Linux messages/syslog, and **addresses,
ids and numbers** (IPv4/IPv6, MAC, UUID, phone numbers, e-mail, URLs, ISO
timestamps, container/git hex ids). Each is a list of regex→colour rules, and
three properties make it safe to leave on:

- **It decorates, never edits.** Only bytes *between* escape sequences are
  looked at; a cursor-movement or title sequence is copied through whole, and a
  sequence that a chunk boundary split in half is carried to the next chunk
  rather than guessed at. What xterm receives is the server's bytes plus
  zero-width SGR sequences — that is asserted byte-for-byte, including all of
  0x00–0xff and a UTF-8 character cut in two.
- **One line, one vocabulary.** A syslog line is not read by the shell rules, so
  “Failed password **for** root” does not turn `for` into a bash keyword; an
  nginx request line is not read as a shell string literal. Each line is
  classified (nginx access/error, syslog, script, otherwise shell) and only the
  matching set paints it. Data shapes are the exception by design: they apply to
  every line, after the vocabulary has had its pick — the client address at the
  start of an nginx line keeps its nginx colour.
- **The program's own colour wins.** When the remote program puts a colour on a
  line — `grep --color`, `ls --color`, a compiler diagnostic, `bat` — the
  highlighter says nothing more about that line. It used to colour its tokens and
  then restore the program's SGR, which made `grep` useless: the match the program
  was pointing at came back in the same local colours as everything around it, so
  what you searched for was the one thing you could not see. Bold and underline are
  style rather than colour, so they do not silence a highlight; an explicit
  foreground/background (palette, 256-colour or truecolor) or reverse video does.
  The latch lasts exactly one line, so a coloured prompt cannot switch the
  highlighter off for the output underneath it. Full-screen programs (alternate
  screen: vim, less, htop) are left completely alone, and no colouring happens
  while a trzsz transfer is running.

**Your own keywords.** The same dialog takes custom rules: a keyword (matched
whole-word, case-insensitive by default), or a regular expression, plus a colour.
They are checked **before** the built-in sets, because an explicit rule is intent;
the built-in sets then fill in what is left. A pattern that does not compile is
refused when you add it, and one that arrives broken from a file is reported,
not obeyed.

**Importing MobaXterm `.msyn` files.** MobaXterm's syntax files are an INI with
one big alternation per colour (`Red=`, `Green=`, …), and `lib/msyn.ts` reads them:

- The colour names map onto the same SGR codes the built-in sets use; `Underline`
  is kept as an attribute.
- Values are split at **top-level** alternations only (respecting groups, classes
  and escapes) so a `|` inside `(a|b)` stays where it belongs.
- Each branch is compiled on its own. A .NET regex and a JavaScript regex are
  close but not identical, and files in the wild are often damaged — the reference
  file in `C:\Users\…\Documents\Custom_ Standard keywords + Shell syntax.msyn`
  is Windows-1252 with several unbalanced groups. The import keeps what compiles
  (20 rules from that file), reports what does not (7 branches, each with the
  reason), and never fails the whole file because of one of them.
- Decoding is strict UTF-8 when possible and Windows-1252 otherwise, so the ASCII
  a regex is made of survives byte for byte.

### The byte pipe

```
remote PTY ── raw bytes ──▶ Go pump (batched ≤64 KiB / 12 ms) ── base64 ──▶ event "ssh:data"
                                                                          │
   xterm.write  ◀── TrzszFilter.processServerOutput  ◀── ServerOutputStream ◀── base64ToBytes ◀──┘

keyboard ──▶ TrzszFilter.processTerminalInput ──▶ sendToServer(string | Uint8Array)
                                                        │ toSendBytes()
                                          UTF-8 for text, raw for bytes
                                                        ▼
                                        base64 ──▶ SendInputB64 ──▶ PTY
```

The JSON bridge cannot carry a raw `0x00`–`0xff`, so everything crossing it is
base64. Strings from trzsz are protocol frames (`#ACT:`, base64 payloads) that
are pure ASCII — identical in UTF-8 and latin1 — while typed text is *not*, and
a remote PTY wants UTF-8. `toSendBytes()` is the one place that decides, and
`frontend/src/lib/trzsz-pipe.test.ts` pins that decision against the real
filter, including a live `::TRZSZ:TRANSFER:` takeover.

### Decisions worth knowing

- **Host keys are trusted on first use, then enforced.** First contact records
  `SHA256:…` in `known_hosts.json`; a later mismatch is a refused connection
  with both fingerprints in the message, not a warning you can click through.
  `Set hostKeyPolicy:"strict"` to reject unknown hosts outright. Forget a pin
  from the sidebar → *Known hosts*.
- **Secrets never enter the webview.** `ConnectHost(id)` resolves the password
  in Go, so the frontend can render a host list without ever holding a
  password. `hosts.json` is safe to read, diff and back up.
- **The secret backend is reported, not assumed.** Windows Credential Manager
  via syscalls (no flashing `cmdkey` console windows). Where that is not
  available — or with `GOTERM_SECRETS=file` — an AES-256-GCM sealed file whose
  key sits in a separate `0600` file; the status bar then says
  *sealed file* instead of implying OS key-ring protection.
- **Output is batched, keystrokes are not.** One event per 12 ms of quiet or per
  64 KiB burst keeps `cat big.log` from generating thousands of IPC calls, while
  typing stays immediate.
- **A session dies through one door.** `Session.finish()` is idempotent: it
  closes pipes, drops the agent connection, and emits `ssh:closed` exactly once,
  whatever raced in — remote exit, write error, tab close, or app shutdown.
- **Element resets live in `@layer base`, never at the top level.** A declaration
  outside every `@layer` outranks all layered rules whatever its specificity, so
  `button { color: inherit }` silently beat the `text-[…]` utilities on every
  button: "New host" and "Save & connect" were painted with the inherited text
  colour — near-black on dark blue in the light theme — Delete lost its red, the
  unselected auth-type options lost their dim, and `font: inherit` (a shorthand)
  reset `font-mono` on every input. It looked like a picked-wrong colour; it was a
  cascade-layer mistake, and the dark theme hid it because there the inherited
  colour happened to suit the bright accent. Both halves are guarded in
  `theme-tokens.test.ts`, which also refuses a token pair below WCAG AA.
- **Files are dropped, not remembered.** Drag onto a terminal to upload (no need
  to type `trz`); `tsz` opens the OS save dialog. The context menu's *Upload files…*
  takes the same path as typing `trz`: the hidden `<input type=file>` it used to
  rebuild into a `DataTransferItemList` produced items with no filesystem entry
  (`webkitGetAsEntry()` returned null), so the picker opened and nothing uploaded.

### 2. 连接、认证与保活

补充说明（都是踩过的坑，别再走回头路）：

- **没存密码的主机不再直接失败**：原来 `SSHConfigWith` 在“密码认证 + 密钥环里没有”时抛一句
  “has no saved password: edit the host and enter it again”——双击一下就是一条红色错误，没有出路；
  而**同一情形下的加密私钥**是会弹窗的。现在两边一致：Go 抛的是**标记**
  （`hoststore.ErrPasswordRequired`，文案 `password required:` / `password required (proxy):`，
  与 `sshx.ErrPassphraseRequired` 同一套写法），前端认这个标记 → 弹 “Password” /
  “Jump-host password”，勾“记住”才写密钥环，取消就是取消。另外前端在**拨号之前**就用
  `host.hasSecret` 先问：空密码发过去只会变成远端的一次失败登录（可能撞账号锁定），而这件事
  GoTerm 连接前就能看见；标记那条留给密钥环条目丢失/`hasSecret` 过期的情况兜底。
  答案现在走 `ConnectAnswers` **结构**，不再是五个同类型位置参数（上一次的 bug 就是目标的口令
  落进了跳板机字段），2FA 的验证码仍追加在这一次实际使用的密码后面。测试：
  `internal/hoststore/password_prompt_test.go`（标记、只用于本次且不落盘、2FA 追加）+
  `app_test.go`（标记断言）+ `frontend/src/lib/login-password.test.ts`（11 条：识别两种标记、
  拨号前先问、记住才存、取消＝标签关闭而不是报错、跳板机口令不会串到目标）。
- **最长会话时长（硬上限）**：保活的作用是“发现链接已经死了”，不是“让一个登录永不结束”——否则就
  是在对抗对面的会话策略。所以上限放在**连接**（`connRef`）上，而不是标签上：默认 12 小时，
  1–24 小时可调，到点直接关掉连接并说明原因（`maximum session lifetime reached (12 hours)`，
  通知里额外说一句“reconnect to continue”，已存主机的那条断开条本来就有 Reconnect 按钮）。
  三个关键性质：①
  **Duplicate 不续命**——复制出来的标签是同一连接的另一个 channel，时钟跟着连接走；
  ② **调小立即生效**——到期时刻算的是 `连接创建时间 + 上限`，不是 `现在 + 上限`，所以“先开 12 小时、
  第 11 小时再改成 1 小时”会当场结束，而不是重新起算（能往前推的上限不是上限）；
  ③ **Go 自己夹紧**——`sshx.SessionLifetime()` 把任何输入夹到 1–24，0/负数按默认 12 处理，
  所以手改配置文件或过期的前端都求不到一个“无限”。前端只是把选的值推过去（`SetSessionLifetime`），
  Go 的 12 小时默认在 UI 没来得及推之前就已经在生效。测试：`internal/sshx/lifetime_test.go`
  （到点真断+通知、Duplicate 共享时钟、调小立即结束、夹紧与文案），前端 `store-settings.test.ts`
  与 `SettingsDialog.test.ts`（默认/夹紧/持久化/推给 Go）。破坏性验证：把 `armLifetime` 短路后
  三条行为测试全部“timed out waiting for the cap”。
- **保活换字符的来龙去脉**：先发回车 → 会把没提交的半行命令直接执行（红线）；改 `\x00`(NUL) 与 `\x1b[0n`(DSR) → 直连和 JumpServer **两边实测都照样超时**，`\x1b[0n` 进 PTY 后是 readline 眼里的垃圾字符；最终"空格+退格"才同时满足"是输入"和"提交不了任何东西"。
- anti-idle 的六道闸门（有未提交输入不发空行、全屏程序不发、传输中不发、输出刚停 5 秒内不发、刷屏一次即本会话放弃并告知、用户真敲过命令后恢复）都是实机故障反推出来的。
- **TUI 里怎么保活**：前两种 nudge 都在备用屏里闭嘴（全屏程序里空格/回车是有意义的按键），所以带输入框的 TUI（自己的闲置计时器）一直没有解。加的第三种 `space-only` 只发 `0x20`：它是真按键，所以能进 TUI，代价是**会留在输入框里**。因此它是显式选项（默认不变），选中时设置里当场写明代价与不该用的场合（`less` 翻页、`fzf` 选中、编辑器插入）。`nudgeBytes()` 是纯函数，三种模式的字节由测试钉住；`SettingsDialog` 的 select 改为把原始值交给 `setIdleNudge`（原先“非 line 即 space”的写法会把第三个值悄悄吞成默认），允许集合只有 `store.ts` 的 `IDLE_NUDGES` 一处。破坏性验证：去掉 tick 里的 `nudge !== 'space-only'` 豁免，备用屏那条测试立刻变红（`expected +0 to be 1`）。

### 3. 渲染、配色与关键字高亮

关于 grep 那条，契约是**有意改掉**的：以前是"我先上色、再把远端的 SGR 回放回去"，
这对 `ls --color` 够用，但 grep 的匹配项正是靠颜色才看得见，被本地同色系一淹就成了
整行唯一看不见的东西。现在规则是：**远端程序在一行里上了自己的颜色，本地这一行完全不
插手**；粗体/下划线算"样式"不算"颜色"，显式前景/背景（含 38;5 / 38;2）与反色算颜色。
若你的 `GREP_COLORS` 是 `mt=01`（只有粗体无颜色），这条规则仍需调整——尚未确认。

关于**切到 light 后当前标签背景仍是深色**：结论是**标签栏属于窗口外壳，必须跟主题走**，自定义
背景只管画布本身。经过：活跃标签原本拿终端画布色（`--term-bg`）去画，好让它和面板“长在一起”
——画布色一旦与主题脱钩（自定义背景在切换明/暗后刻意保留），light 主题下就留下一个深色标签。
第一版修法是把标签文字换成画布墨色（`--term-fg`）：字读得清了，但标签仍旧不跟主题走——你指出
这才是真问题，所以改成活跃标签用 `--bg`（主题底色）+ `--text`，画布色一律不进外壳。现在有一条
静态守卫测试（`components/chrome-theme.test.ts`）扫描所有组件：只有 `TerminalPane.vue`（画布
宿主）与 `SettingsDialog.vue`（终端预览）允许出现 `--term-` 令牌，其余外壳组件出现即失败。

关于 **`dust` 柱状图粘连**：不是 dust 的问题，是 xterm 的画法。`customGlyphs`（xterm 6 默认开）让它
自己画块元素与制表符，并且**铺满整个单元格**——包括本应用 `lineHeight: 1.15` 的那 15% 留白。于是
`dust` 每个目录一行 `█`，上下两行之间没有空隙，八行条形图糊成一整块。
真正的变量是“块字符由谁画”：交给字体就恢复留白，八行各成一条。
这两张图是用同一份 xterm 6 + 它的 WebGL 渲染器（本应用加载的那个）在无头浏览器里渲出来的，不是猜的；
代价也在同一张图里：字体的 `│` 同样跨不过留白，`htop` 之类 TUI 的竖边框会出现发丝缝。两者不可兼得
（xterm 只提供“全画”或“全不画”一个开关），所以做成了设置项 **Appearance → Block and box
characters**，默认关（要柱状图分行），改动即时生效（`term.options.customGlyphs` + `term.refresh`；
WebGL 渲染器会因该选项重建字形图集，不用重开标签）。钉住它的测试：`lib/terminal-glyphs.test.ts`
（默认 false、显式 true、已开标签可切换）、`lib/store-settings.test.ts`（默认值/持久化/非法值拒绝/
reset 归位）、`components/SettingsDialog.test.ts`（控件）。

关于**中文乱码**：先排除了渲染侧——`frontend/src` 全部 vue/ts/html/css 都是合法 UTF-8，
`index.html` 声明 `charset=UTF-8`，系统装了含 CJK 的字体（SimSun / 微软雅黑 / 等线 …），
并用同一份 xterm 6 以本应用真实字体栈在无头浏览器里渲染中文、制表符表格，截图为证：中文与对齐都正常。字节管道本来就是**逐字节保真**的
（`paint()` 是远端字节进 xterm 的唯一咽喉，0x00-0xff 与“被切开的 UTF-8”都有断言），
所以乱码只可能来自**远端发出的不是 UTF-8**——`zh_CN.GBK` 的老服务器至今不少见。
于是新增 `lib/encoding.ts` 的 `RemoteTextDecoder`：UTF-8 仍然返回**同一个 `Uint8Array` 实例**
（默认路径不可能悄悄偏离逐字节语义），其余编码走**流式** `TextDecoder`（`decode(bytes,
{stream:true})`，一个 GBK 汉字被 64 KiB 输出块切开也不会变成两个替换字符），换编码时丢弃
半个字符。设置入口在 Appearance → **Remote text encoding**，改完立即作用于所有已开标签。
已知边界：**输入仍按 UTF-8 发送**（浏览器没有 GBK 编码器）；远端要 GBK 输入的，建议在上面
`export LANG=zh_CN.UTF-8` 并留在 UTF-8。

### 4. 键盘与鼠标归属

关于**搜索**：用的是 xterm 官方的 `@xterm/addon-search`（本来就已在依赖里），所以匹配落在
**缓冲区的真实内容**上，不是把屏幕文本抓出来自己再找一遍；`onDidChangeResults` 回报的
`resultIndex/resultCount` 就是搜索条上那个 `2 / 7`。键位选 `Ctrl+Shift+F` 而不是 `Ctrl+F`：
后者给 readline 是 `\x06`（向前移一个字符），抢了就真没人能打字了；而 `Ctrl+Shift+F` 落在
`appOwnsKey()` 范围内，xterm 会把事件让给应用，不会先发给 shell（`lib/shortcuts.test.ts`
同时钉住“`Ctrl+F` 归 shell、`Ctrl+Shift+F` 归应用”）。搜索条只在**当前活跃标签**上出现：
`open` 状态放在 store（哪个标签按键都能开），查询词与“区分大小写”留在 pane 自己身上（每个标签
搜自己的缓冲区），切标签时自动收起，因为别的标签的计数是假的。匹配高亮用主题令牌
（`--selection` / `--accent`）现算，不写死颜色；回车下一个、`Shift+回车` 上一个、`Esc` 关掉
并把键盘还给终端（`TerminalPane.test.ts` 里 8 条用例包含这一条）。

两条边角是找出来后补的，都不是“看起来对不对”的问题：

1. **“切标签就收起”必须是所有路径**，不只是点标签条。连接新主机、Duplicate、Reconnect、
   关掉最后一个标签都直接改 `state.activeTabId`，绕过了 `activateTab`。原来那条在
   `activateTab` 里的清理因此只能盖住一条路：在 A 里搜出 `3 / 12`，再去点侧栏连一台新主机，
   条会**留在新标签 B 上、带着 A 的数字**；而回到 A 时 `closeFind()` 清的是此刻“活跃”的 B，
   A 的高亮再也清不掉——更糟的是 addon 会把它缓存的搜索词继续应用到 A 之后每次输出上。
   现在收起的动作只在 store 里一处（`watch(() => state.activeTabId, …, { flush: 'sync' })`），
   并且清的是**被离开**那个标签（`closeFind(tabId)`），新的路径不可能忘。
2. **计数可能是 `? / 1000`**。addon 累计到 1000 个匹配就不再收（`highlightLimit`），选中项
   不在这个窗口里时 `resultIndex` 是 -1——早先直接 `+1` 会显示成 `0 / 1000`，与“没找到”
   长得一模一样。现在未知索引显示 `?`。

另外，输入框里的 `Esc` 在 **IME 组词中**不拦（`event.isComposing`）：那一下属于候选窗，抢了就
是把半截拼音卡在原地。

### 5. 标签与会话管理

关于**已断开标签的输入**：关掉的标签不会卸载（它要显示那条断开条），所以仍然会收到一切活会话
会收到的信号——切回它时 xterm 发的 focus-in 序列、程序申请了鼠标时的点击报告、anti-idle 的
nudge。这些以前都走 `onSend`，每个都以 “session is closed” 失败并弹一条 toast，于是回到一个
死标签就像被同一句话刷了屏。现在规则收成两条：`acceptsInput(tab)`（有 sessionId 且
`status === 'open'` 才允许发）与 `markSessionGone(tab, message)`（标 closed、把原因写进 pane、
**停掉 anti-idle**、不弹 toast）。另外 `pushNotice` 加了一层 4 秒内同文本去重：同一句话是回声
而不是新闻。测试在 `frontend/src/lib/dead-session.test.ts`；`onSend` 本身在无头环境里摸不到
（xterm 的输入要真的打开终端），所以测的是这两条规则，测试文件头写明了这个限制。

### 6. 文件传输

**`rz` 上传为什么会死在弹窗上（已修）**：`rz` 是“服务端收”，我们是发送方。选文件要人动手，
而同一时刻 zmodem.js 每 5 秒跑一次所谓 keepalive（发 ZSINIT，并把“下一个可接受的头”改成只剩
`{ZACK}`，或者干脆清空）。lrzsz 的 `rz` 在等 ZFILE 期间会用 `ZRPOS`（它当前想要的偏移）周期性
ping 回来——正好落进这个窗口，库就抛 `Unhandled header: ZRPOS`。这条异常从 `Sentry.consume()`
里抛出、被 `feed()` 捕住，而旧代码只做了一件事：把扫描器标成坏掉、弹提示——**会话对象却还挂着**，
于是按键继续被吞、`rz` 永远等不到文件，整个标签看起来就是死的。现在两处都改了：文件对话框打开
期间，`ZACK/ZRINIT/ZRQINIT/ZRPOS/ZSINIT` 这类“我还在这儿”的头一律按无操作放行（库自己安排的头
仍然优先；`ZFILE/ZDATA/ZEOF/ZSKIP/ZABORT` 依旧会抛，因为吞掉它们等于让传输静默挂死）；而会话
一旦抛异常，就正经结束它（向对端发 abort、把键盘给回来），提示改成“ZMODEM ended: …，可以重新跑
rz / sz”。两条都钉在 `zmodem.test.ts › a receiver that polls while the picker is open`：先把时间
推过 5 秒让 keepalive 生效，再用库自己的 `_send_header('ZRPOS', 0)` 模拟 `rz` 的 ping；另一条
验证异常后 `active()` 必须为 false（否则键盘永远拿不回来）。**仍属 🧪**：测试环境没有 lrzsz，对端仍是
zmodem.js 自己的会话，真正的 `rz` 只能你在服务器上再点一次。

**`sz`（下载）现在是好的**：lrzsz 的 `sz` 先发 **ZRQINIT**，扫描器认这个，所以能唤醒会话。
之前台账里“只有 lrzsz 的主机上 `sz` 根本无法唤醒客户端”的说法是**错的**，你的实测（`sz` 正常）
也是证据。剩下的缺口只有一个窄得多的情形：**裸 ZFILE**——一个跳过 ZRQINIT 直接抛 ZFILE 的
发送端——不会被扫描器当成会话开始（实测 `ZFILE → NONE`）；“收到裸 ZFILE 就自建接收会话”那版
实测会在该头上 `CRC check failed!`，已回退。`zmodem.test.ts` 里有一条以缺口命名的测试钉住它。

**ZMODEM 的进度条：直接用 trzsz 那个渲染器（vendor 上游文件），画在终端里**。`rz` / `sz` 自己的进度画在
**服务器那端**的 tty 上，本窗口一个字也看不到——几百 MB 的文件就成了“发出去之后沉默几分钟”。现在
`lib/zmodem.ts` 自己数字节（收：每个 `input` 包累加，总量用 ZFILE 里的 size；发：本地文件 `size` 对已发出的
offset），然后交给 **`TextProgressBar`**——就是 `trz`/`tsz` 用的那个类，按它自己的调用顺序喂：`onNum`，然后每个
文件 `onName` / `onSize` / `onStep` / `onDone`。于是两种传输画出来的是**同一行**（同一份代码）：
`(1/2) backup.tar [████░░░░] 45% | 5.6 MB | 1.2 MB/s | 00:12 ETA`，而且应用里不必为它多出 store 字段、组件
标记和样式。**为什么是 vendor 而不是 import**：包里只导出 `TrzszAddon`/`TrzszFilter`，`TextProgressBar` 在
bundle 里但导不到；所以从发布包的 sourcemap（`lib/trzsz.mjs.map`，版本 1.1.6）取出 `src/progress.ts` **原样**
放进 `frontend/src/vendor/trzsz/`（MIT，版权头保留），旁边一个几行的 `comm.ts` 只放它 import 的那个
`ProgressCallback` 类型，好让上游文件一个字都不用改；唯一加的一行是 `// @ts-nocheck`（本仓库 tsconfig 比上游
严：verbatim module syntax、类字段初始化、noUncheckedIndexedAccess）。这样效果**逐像素一致**，代价是上游将来
改了这个文件要手工同步（1.1.6 至今没动过）。
粘合层只有三处，都在 `zmodem.ts`：`onStep(0)` 让进度条**立刻**出现（trzsz 本来要等第一个数据包，而大文件握手
要几秒）；结束前按**字节数**判断是 100% 还是擦掉（ZFIN 可能在最后几个字节还在落盘时就到，不能把“会话结束”
当“传完了”）；以及补一个换行再 `showCursor()`——trzsz 的条子是原地重绘、换行留给后面打印的东西，这里后面就是
shell 提示符，不补换行会落在条子中间。
测试：`src/vendor/trzsz/progress.test.ts` 守住“这仍是上游的文件”（licence 头、唯一那行 import、没有本地改动
痕迹），并钉住 0%/50%/100%、原地重绘、`(2/3)` 编号、窄终端不折行；`zmodem.test.ts › progress while a file moves`
三条（下载画出条子并以换行+光标结束、多文件 `(1/2)`→`(2/2)`、取消弹窗一条都不画）；
`zmodem-terminal.test.ts` 一条走**真实终端管道**、断言这些字节真的进了 `term.write`。

### 7. 界面、主题与设置

**light 主题下按钮为什么是“蓝底黑字”**：不是配色选错，是 **CSS 层叠层级（cascade layers）**。`style.css` 里那句
`button { font: inherit; color: inherit }` 写在所有 `@layer` 之外，而未入层的规则**无论选择器多简单都优先于
任何入层规则**，于是它把每个按钮上的 `text-[var(--accent-ink)]` 工具类全顶掉了：按钮拿的是“继承来的文字
色”——dark 主题下恰好是浅字配亮蓝（没人看出问题），light 主题下就是近黑字配深蓝（#0b62c4），也就是你截图
里的那个。同一个坑还静吞了 Delete 的红色、认证类型未选中项的暗色，以及所有输入框上的 `font-mono`（`font:`
是简写，连字族一起重置了）。修法是把这几个元素重置收进 `@layer base`（它仍然能作为默认值，但工具类能赢）。
证据不是猜的：拿无头浏览器加载**真正发布的 CSS**，用从组件里抄下来的原始 class 量 `getComputedStyle`——修前
`light newhost bg=rgb(11,98,196) color=rgb(31,41,51)`，修后 `color=rgb(255,255,255)`；Delete 从继承色变回
`rgb(207,34,46)`；`font-mono` 也回到等宽。

新增 `lib/theme-tokens.test.ts` 把这类问题钉成规则：（1）**不允许任何未入层的元素选择器设置 color/font**
（扫描 style.css，跳过 `@layer` 包裹的部分）；（2）**两套主题的令牌对必须算得过 WCAG AA**（accent 与
accent-ink、text/text-dim 与 bg/panel/panel-2、accent 当标题色时的对比度，两套都要达标）。两条都做过破坏
件验证：手动把 `button{color:inherit}` 抖回层外、或把 light 的 `--accent-ink` 改成 `#1f2933`，测试均变红。
副作用：**dark 主题的强调色按钮文字现在按设计变成深色墨**（`--accent-ink: #04121f`，对比度 7.6:1，比之前的
浅字更高），这是 `--accent-ink` 这个令牌一直以来的含义，之前被层级问题顶着没生效。

**哪些事不弹窗**：连接成功、复制标签、会话断开这三件事不再冒右上角提示。理由不是“省一个弹窗”，
而是它们都已经有更靠近现场的载体——连接成功＝标签变绿＋远端自己的横幅；复制＝新标签已经出现、已连上、
已聚焦；断开＝标签变灰＋面板里那行 `[goterm] <原因>`。而弹窗只在**用户不看着那个位置**时才有价值，
所以保留的是这些东西：主机密钥首次信任的警告、传输失败、以及一切需要人做决定的事。**意外断线也不再弹**
（连不上、掉线、Keepalive 判死都只写进面板与标签状态）；要不要为**后台标签掉线**单独补一种提示，
见文末“待你决策”。`via 跳板机` 原本只在那条连接提示里出现过，现在由状态栏承担（它本来就承诺显示）。

测试上钉了两处：Go 侧断言成功连接**不**产生 “connected to” 通知但 `KeepAliveSeconds` 仍可读；前端
断言复制标签后通知列表为空。

### 9. 输入法与本地化

第一条你要求先跳过；第二条是后来报的**更具体**的症状，已定位并修。根因不在输入法，而在焦点：
`App.vue` 用 `v-show` 切标签，而 `activateTab` 是**同步**调 `term.focus()` 的——那一刻新窗格还被
`display: none` 藏着，而 Chromium 对隐藏子树里的元素 `focus()` 是空操作，于是焦点留在**即将被隐藏**
的那个窗格里。Windows 看到“有焦点、却没有任何东西在渲染它”，就把输入法标成禁用（那个红叉）。
两处修复：

1. `activateTab` 改成 `nextTick` 之后、且只在窗格真的可见时才把键盘交给终端（点击终端那条路仍
   立即聚焦，因为它的窗格本来就可见）。
2. 新增 `reclaimFocus()`：窗口或网页重新可见时，如果焦点在“无处”或已隐藏的节点里，就把它收回
   当前终端的窗格；焦点在对话框输入框或按钮上时**不动**——不能把用户手里的键盘抢走。

测试在 `frontend/src/lib/ime-focus.test.ts`（5 条：同步聚焦会失败、点击路径仍即时、从隐藏窗格
夺回、对话框不抢、没有终端也不炸），并做了破坏性验证：改回同步聚焦、或短路 `reclaimFocus()`，
对应测试立刻变红。仍属 🧪——真正的输入法行为只能由人在真实桌面上确认。

### 11. 整体体检（2026-10-28：四个专项审查 + 实测）

判定：**架构方向不用改**。`app.go` 只做绑定（约 35 个方法、每个都很短），真逻辑全在 `internal/*`；
`sshx` 的包注释声称“不 import Wails”，grep 核实 **`internal/**` 里 0 处**导入 wails，诚实；依赖单向
`main → hoststore → sshx / secrets`，无环；`session.go` 的 pump 是唯一出口、`link` 的引用计数是
“客户端比第一个关掉的标签活得久”的实现，Duplicate 先拿连接再开通道——都是有意的正确决定。
要处理的是**长期修补留下的平行机制**，以及几个具体的死代码和**无超时点**。

### 11.1 可直接开工的问题

1. ~~**跳板机/直连的握手没有超时**~~ **已修（2026-10-28）**：查了 `golang.org/x/crypto/ssh@v0.57.0`
   —— 整个包**从不调 `SetDeadline`**，唯一的几处是 `chanConn` 的桩，直接返回
   `"ssh: tcpChan: deadline not supported"`。所以 `ClientConfig.Timeout` 只管 TCP connect，
   **读 banner 和密钥交换完全无超时**；跳板机那段还多一个 `bastion.Dial`（direct-tcpip 通道请求，
   同样无超时）。结果：对“接受了连接然后一声不响”的对端（死端口转发、指向空气的堡垒机、没有后端的
   负载均衡），`Connect` **永远不返回**，窗口一直转圈。修法：
   `handshake()` 用 `AfterFunc` 到点关连接把握手顶回来（错误文案统一成 `no answer from … within …`），
   `openTunnel()` 用 `select` + `time.After` 框住通道打开（超时就关掉堡垒机连接把请求撤了，
   结果走 buffered channel，不泄 goroutine）。测试在 `internal/sshx/stall_test.go`：一个只 accept
   不说话的 TCP listener，一条直连、一条隔着跳板机，都是 300 ms 内报错收场。
   **破坏性验证过**：把 watchdog 改成 1 小时后，同一测试 `-timeout 25s` 直接
   `panic: test timed out after 25s`——它袖住的正是“永远不返回”。
2. **`resetSettings()` 漏了 `theme`**（中）：12 个设置键复位 11 个，
   `frontend/src/lib/store.ts:406-419`。按钮写“恢复默认”却没恢复主题——要么补上（行为变更，
   要你确认），要么在注释里写明为什么主题不归它管。
3. **`Session` 上三个只写不读的字段**（中，误导）：`conn`（`manager.go:269` 赋值，全仓无读）、
   `bastion`（`:272`，注释说“read for reporting only”是假的——`Info()` 走 `cfg`/`link`）、
   `keepAlive`（`:276`，`Info()` 读的是 `link.every`）。定义在 `internal/sshx/session.go:66/71/80`。
4. **切标签时两条聚焦路径并行**（中）：`activateTab` 走 `nextTick → focusIfShown`（正确的），而
   `TerminalPane.vue:57-64` 的 `props.active` watcher 还在**同步** `bridge.focus()`——正是台账§9 说已
   废弃的那条（pre-flush 时窗格仍隐藏 → 空操作）。今天靠调用顺序侥幸不炸，谁调一下顺序就
   复现“已禁用输入法”红叉。修法：watcher 只留 `fitNow()`，聚焦一律走 `focusIfShown`。
5. **一次连接失败有四种表达**（低，产品取向）：`status='error'` + `tab.detail` + sticky toast +
   终端里那行 `[goterm] …`（`store.ts:1291-1305`）。不是 bug，是没定过“一个事实几个载体”。

### 11.4 体积：实测与三条路

基线：`bin\goterm.exe` **11,830 KB**；同一份源码不 strip 是 **16,511 KB** —— 现有
`-tags production -trimpath -buildvcs=false -ldflags="-w -s -H windowsgui"` 已经省了 4.7 MB。
拆开看：**前端只占 7.6%**（`frontend/dist` 894 KB：JS 864 + CSS 30），**92.4% 是 Go + Wails v3 +
WebView2 COM + x/crypto/ssh + syso**。所以“精简 JS”不是主战场。gzip 压一遍整包是 4,601 KB（39%）。

- **路 A｜UPX**：预计落到 **4.5–6 MB**。代价：未签名 + UPX 壳是杀软启发式的经典靶子（Defender 误报）、
  启动多 100–300 ms、要额外下载 upx.exe。**需要你授权联网装第三方工具**。
- **路 B｜dist 压成 zip 再 embed**：894 KB → **260 KB（实测）**，而 flate/zip 已在依赖图里，
  所以净省 ≈ **630 KB（5%）**。代价：`build/windows/Taskfile.yml` 的 `build:native` 要多一步产 zip，
  `zip.Reader` 做 `fs.FS` 需要把条目名归一化成 `/`（PowerShell 的 `Compress-Archive` 写的是反斜杠），
  资源服务要重验一遍。**单文件便携不受影响**。
- **路 C｜self-test 挪出生产包**（build tag）：估 150–400 KB（未实测），代价是正式包里 self-test 按钮失效。
- **不值得**：删 xterm 插件各别 <1%（webgl 124 KB、unicode-graphemes 33 KB、search 38 KB），
  换掉的是渲染质量或刚做好的搜索。

| A toast never sits on top of a session's own buttons | `frontend/src/components/NoticeStack.test.ts` pins the stack to the top-right: it used to be anchored bottom-right, where its `pointer-events-auto` card covered the closed-session **Reconnect / Close tab** buttons — and an error toast never auto-dismisses, so those buttons stayed dead |
| Selecting copies — but only a selection you dragged | `frontend/src/lib/paste-flow.test.ts` → *copy on select*: a release after a press inside the pane copies; a release with no press copies nothing; the setting off copies nothing; an empty selection writes nothing |

Honest gaps: no host running real `trz`/`tsz` binaries was reachable here, so
wire compatibility is proven against `sshtest -shell trzsz` (a second,
independent implementation of the server side) rather than against trzsz's own
go binaries. Synthetic input into the webview is blocked by UIPI in this
environment — the right-click menu, the tab menu and the settings screen are
covered by component tests, and `gui-transfer.ps1` needs a real desktop session
(it says so when it cannot take the foreground). Keyword colouring is therefore
proven at the byte level and at the pipe boundary, not by looking at a
screenshot of a real session. `-race` is unavailable with this toolchain (no
cgo/gcc), so the shared-connection refcount is exercised by the ordinary suite
rather than by the race detector.

## D. 原始立项计划

### 附录 A：原始立项计划（原文保留）

基于 **Wails (Go) + xterm.js + trzsz** 的架构，我们将整个桌面端 SSH 工具的研发划分为 **5 个循序渐进的阶段（Sprint）**。每个阶段都有明确的交付产物和验证标准，确保你能够步步为营，最快在第 2 阶段就能看到能跑的终端，第 3 阶段彻底解决下载乱码问题。

### 项目技术栈清单
- **后端**：Go 1.21+，`golang.org/x/crypto/ssh`，Wails v2
- **前端**：Vue 3（或 React）+ TypeScript + TailwindCSS
- **核心组件**：`@xterm/xterm`，`@xterm/addon-fit`，`@xterm/addon-webgl`（性能加速），`trzsz`（前端 SDK）
- **本地存储**：BadgerDB 或轻量级加密 JSON 文件（保存主机列表）

### 第一阶段：项目脚手架与基础通信链路 (Day 1 - Day 2)

**目标**：跑通 Wails 前后端架构，打通 Go 与 Vue/TS 的双向事件流（IPC）。

### 开发步骤：
1. **环境准备与初始化**
   ```bash
   # 安装 Wails
   go install github.com/wailsapp/wails/v2/cmd/wails@latest
   # 创建 Vue-TS 模版项目
   wails init -n modern-ssh -t vue-ts
   cd modern-ssh
   ```
2. **定义前后端通信契约**
   - **Go -> Frontend (数据下发)**：使用 Wails 的 `runtime.EventsEmit(ctx, "ssh:data", data)` 推送远程终端的输出流。
   - **Frontend -> Go (输入上传)**：在 `App` 结构体暴露方法，Wails 会自动生成 TS 绑定代码：
     - `Connect(config SSHConfig) (string, error)` (返回 session_id)
     - `SendInput(sessionID string, data string)`
     - `ResizePTY(sessionID string, cols int, rows int)`
     - `CloseSession(sessionID string)`

3. **前端安装核心依赖**
   ```bash
   cd frontend
   npm install @xterm/xterm @xterm/addon-fit trzsz
   npm install lucide-vue-next # 现代化图标库
   ```

**交付产物**：点击前端按钮，可以调用 Go 后端打印日志，Go 可以定时向前端推送一段字符串。

### 第二阶段：核心 SSH 通道与终端渲染 (Day 3 - Day 5)

**目标**：实现真正的远程连接，在前端网页上渲染出可以打字、响应 `vim`/`top` 的全功能终端。

### 开发步骤：
1. **后端实现 Session 管理器 (`ssh_manager.go`)**
   - 封装一个全局 `SessionManager`，用 `map[string]*SSHSession` 管理连接实例。
   - 实现 `golang.org/x/crypto/ssh` 的拨号逻辑，支持密码认证和私钥认证（加载本地 `id_rsa`）。
   - 创建 `ssh.Session`，调用 `RequestPty("xterm-256color", rows, cols, modes)` 申请伪终端。
   - 启动两个 Goroutine：
     - 一个负责监听 `session.StdoutPipe()` / `StderrPipe()`，通过 Wails 事件将数据以 Base64 或原始二进制数组推给前端。
     - 一个负责等待会话结束并清理内存。

2. **前端封装终端组件 (`XtermView.vue`)**
   - 实例化 `new Terminal({ cursorBlink: true, fontSize: 14, fontFamily: 'Fira Code, Consolas' })`。
   - 加载 `FitAddon`，让终端自动填满容器大小。
   - 监听终端输入：`term.onData(data => SendInput(sessionId, data))`。
   - 监听后端输出：`EventsOn("ssh:data", data => term.write(data))`。
   - 监听窗口 Resize，调用 `fitAddon.fit()` 计算新的行列数，触发 `ResizePTY(sessionId, cols, rows)`。

**交付产物**：输入远程 Linux/WSL 的 IP 密码后，弹出黑框，成功进入 bash，可以正常使用 `ls`、`vim`、Tab 补全，终端拉伸时光标自适应。

### 第三阶段：集成 trzsz，消除乱码 (Day 6 - Day 8) 【核心攻坚】

**目标**：彻底解决 `lrzsz` 的乱码问题，在前端无缝拦截 `trz` / `tsz` 并实现可视化进度条传输。

### 开发步骤：
1. **前端接入 `trzsz.js`**
   - 官方提供的 `trzsz` 前端 npm 包是专门为 `xterm.js` 设计的。它的原理是作为一个"中间层"拦截 `xterm.onData` 和后端的原始流。
   - 在 `XtermView.vue` 中改造数据管道：
     ```typescript
     import { TrzszFilter } from 'trzsz';

     // 初始化 trzsz 过滤器
     const trzszFilter = new TrzszFilter({
         writeToTerminal: (data) => term.write(data),
         sendToServer: (data) => SendInput(sessionId, data),
         // 当远端触发 trz/tsz 时，trzsz 自动接管原生拖拽/文件选择
         terminalColumns: term.cols,
         isWindows: false, // 目标服务器环境
     });

     // 改造监听：后端来的数据不再直接 term.write，而是先过 filter
     EventsOn("ssh:data", (base64Data) => {
         // 解析为二进制 Uint8Array
         const uint8 = base64ToUint8Array(base64Data);
         // Filter 会自动嗅探特征码，非传输状态直接传给 term.write
         // 嗅探到传输特征码，自动暂停终端回显，唤起浏览器的文件选择窗！
         trzszFilter.processServerOutput(uint8);
     });

     // 用户键盘输入也要经过 filter
     term.onData((data) => {
         trzszFilter.processTerminalInput(data);
     });
     ```

2. **适配多文件与目录拖拽（可选高级特性）**
   - 监听终端 DOM 容器的 `dragover` 和 `drop` 事件。
   - 将拖入的文件直接交给 `trzszFilter.uploadFiles(files)`，无需手动在终端敲 `trz` 命令。

3. **远端 Linux/WSL 安装配套服务端**
   - 验证前，确保 WSL 中安装了 trzsz（客户端与服务端必须配合）：
     `sudo apt update && sudo apt install -y python3-pip && pip3 install trzsz` 或直接复制 release 二进制。

**交付产物**：
- 在终端输入 `tsz <大文件>`，前端**自动弹窗**询问保存位置，并自带原生传输进度条，下载的文件 md5 与服务器一致，**绝无乱码**。
- 输入 `trz`，弹窗选择文件并极速上传。

### 第四阶段：现代化桌面 UI 与会话管理 (Day 9 - Day 11)

**目标**：摆脱简陋的调试界面，打造成媲美主流商业软件（如 Termius、FinalShell）的现代化应用。

**交付产物**：拥有现代侧边栏、Tab 标签页，并能持久化保存多个服务器配置的完整桌面客户端。
